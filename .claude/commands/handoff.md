지금까지의 작업 상태를 다른 기기/다른 세션에서 바로 이어갈 수 있도록 `docs/handoff.md`에 저장한다.
이 파일은 **매번 덮어써서 갱신**한다(누적 로그가 아니라 "지금 시점의 스냅샷"). `docs/` 폴더가 없으면 만든다.

## 먼저 확인할 것
- `git branch --show-current` (현재 브랜치)
- `git status --short` 와 `git log --oneline -5` (커밋 안 된 변경, 최근 커밋)
- 오늘 날짜

## 파일 형식
헤더에 날짜와 현재 브랜치를 쓴다.

```
# 작업 인수인계
- 날짜: YYYY-MM-DD
- 브랜치: <git branch --show-current 결과>
- 기준 커밋: <짧은 해시와 메시지>
```

섹션은 아래 순서와 이름 그대로 쓴다.

1. **목표** — 지금 하고 있는 일이 무엇이고 왜 하는지. 2~4줄.
2. **완료한 것** — 끝난 작업을 항목으로. 파일/폴더 이름은 적되 코드는 붙이지 않는다.
3. **결정 사항** — 정한 것과 그 이유. **검토했다가 버린 대안과, 버린 이유를 반드시 함께** 적는다
   (다음 사람이 같은 대안을 다시 검토하느라 시간을 쓰지 않도록).
4. **현재 상태·주의** — 커밋 안 된 변경, 테스트 중인 것, 알려진 문제, 이 기기에만 있는 것(대화에서만 받은 자료, 로컬 설정 등),
   함정(실수하기 쉬운 점).
5. **다음 단계** — 바로 착수 가능한 구체적 작업을 **순서대로** 번호를 매겨서. 막연한 항목("개선", "정리")은 쓰지 않는다.
   각 항목에 "무엇을 / 어느 파일에서 / 끝났다고 볼 기준"이 드러나게 쓴다.

## 쓰지 말 것
- 대화 로그, 대화 내용 요약 나열
- 코드 diff, 코드 덩어리 (필요하면 파일 경로와 함수/클래스 이름만)
- 이미 코드나 git 기록으로 알 수 있는 것의 장황한 반복

## CLAUDE.md에 들어갈 영구 규칙
이번 작업에서 "앞으로 항상 지켜야 하는 규칙"이 새로 생겼다면 handoff에 넣지 말고,
응답 마지막에 **"CLAUDE.md에 추가를 제안하는 규칙"**으로 따로 제안한다(내가 승인하면 반영). 없으면 "없음"이라고 쓴다.

## 마지막
`$ARGUMENTS`가 있으면 파일 맨 끝에 **"추가 메모"** 섹션으로 그대로 반영한다. 없으면 이 섹션은 만들지 않는다.

작업이 끝나면 파일 경로와 섹션별 한 줄 요약만 보여준다(전체 내용을 다시 출력하지 않는다).
