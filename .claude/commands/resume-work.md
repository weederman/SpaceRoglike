description: docs/handoff.md를 읽고 이전 작업 이어가기 (기기 이동 후 실행)
---

다른 기기/세션에서 하던 작업을 이어받는다. **내가 승인하기 전에는 코드나 파일을 수정하지 않는다.** (읽기와 git 조회만 한다)

## 순서

1. `docs/handoff.md`를 읽는다. 파일이 없으면 "인수인계 파일이 없습니다. 이전 기기에서 /handoff를 먼저 실행해야 합니다."라고 알리고 멈춘다.
2. `git branch --show-current`로 현재 브랜치를 확인하고, handoff 헤더의 브랜치와 비교한다.
   **다르면** 두 브랜치 이름을 보여주며 경고하고 **거기서 멈춘다.** (브랜치를 마음대로 바꾸거나 이어서 진행하지 않는다. 어떻게 할지는 내가 정한다.)
3. `git log --oneline -10`으로 handoff 이후에 생긴 커밋이 있는지 확인한다. handoff의 "기준 커밋" 뒤에 커밋이 더 있으면 어떤 것인지 알린다.
   `git status --short`로 커밋 안 된 변경도 확인한다(UI 팩 폴더의 변경은 사용자의 임포트 작업이니 무시).
4. 아래를 보여준다.
   - **상태 요약 3~5줄**: 목표, 어디까지 끝났는지, 알아야 할 주의점(특히 "이 기기에만 있는 것"으로 적힌 항목이 지금 기기에 있는지)
   - **"다음 단계 1번" 실행 계획**: 어떤 파일을 어떻게 바꿀지, 어떻게 확인할지(Play 모드 검증 방법 포함), 예상되는 위험
5. "이 계획으로 진행할까요?"라고 묻고 **내 승인을 기다린다.** 승인 전에는 코드 수정, 파일 생성, 커밋을 하지 않는다.

CLAUDE.md의 규칙은 항상 따른다. handoff에 "자료가 이 기기에 없다"는 항목이 있으면 계획에 앞서 내게 그 자료를 요청한다.
